# Day04: інструменти оркестрації та перенесення роботи

Перевірено за офіційною документацією **2026-09-16**.
Основна лабораторна — `06-scoped-export`; сценарії та розподіл роботи визначає її специфікація.
Приклади нижче — шаблони: цей документ не встановлює конфігурації й не запускає агентів.

## Почати в Codex

Делегування можна попросити звичайною мовою; у CLI `/agent` показує потоки агентів.
Доступність залежить від поточного інтерфейсу та інструментів сесії.
Спочатку попросіть перевірити доступні можливості; за їх відсутності виконайте ті самі ролі послідовно.
[Офіційна документація OpenAI](https://learn.chatgpt.com/docs/agent-configuration/subagents).

```text
Продовжуємо Token Atlas: change 06-scoped-export.
Прочитай AGENTS.md, docs/PRD.md, docs/architecture.md та артефакти change.
Перевір, чи в цій сесії доступні інструменти запуску субагентів.
Якщо доступні, організуй двох виконавців і незалежного перевіряльника.
Не імітуй делегування текстом. Якщо недоступні — виконай ролі послідовно.
Спочатку зафіксуй контракт, сценарії, власників файлів і залежності.
Делегуй лише незалежні задачі; спільні файли та інтеграцію залиш собі.
Кожному передай дозволені файли, критерій готовності та умови зупинки.
Перевіряльник шукає контрприклади до специфікації та не виправляє код.
Після інтеграції виконай обов'язкові перевірки репозиторію.
Збережи фактичні результати й невиконані перевірки в build-log.
Використовуй доступну модель; запиши її фактично спостережений ID.
```

Два виконавці можуть працювати одночасно лише після узгодження інтерфейсу.
Перевіряльник спочатку готує негативні сценарії, а після інтеграції оцінює результат.
Він не повинен робити висновок про фінальну версію за проміжним станом файлів.

За потреби Codex підтримує окремі TOML-файли в `.codex/agents/`.
Ліміт нижче рахує дочірні потоки без головного; `max_threads` — старий псевдонім.
Дочірні агенти успадковують sandbox, а активні перевизначення батьківської сесії можуть змінити ефективні права.
Перевірте їх перед демонстрацією, не покладайтеся лише на файл.
[Конфігурація субагентів](https://learn.chatgpt.com/docs/agent-configuration/subagents).

```toml
# Приклад .codex/config.toml
[agents]
max_concurrent_threads_per_session = 3
```

```toml
# Приклад .codex/agents/acceptance-checker.toml
name = "acceptance_checker"
description = "Перевіряє реалізацію за сценаріями приймання."
sandbox_mode = "read-only"
developer_instructions = """
Шукай контрприклади. Наводь файли та кроки відтворення.
Відокремлюй підтверджені дефекти від відсутніх доказів.
Не виправляй код і не делегуй роботу далі.
"""
```

## Права: інструкція та технічне обмеження

«Не змінюй файли» — інструкція для поведінки; обмежений набір інструментів або sandbox — контроль можливостей.
У Claude Code правила permissions застосовує середовище, а не модель.
Агент із довільним shell-доступом може змінювати файли навіть без Edit/Write.
[Permissions](https://code.claude.com/docs/en/permissions).

Для огляду коду достатньо інструментів читання.
Для виконання тестів потрібен окремо дозволений запуск команд: build і тести можуть створювати артефакти.
Тому в базовій лабораторній перевіряльник читає код і докази, а інтегратор запускає перевірки.
Незалежність перевірки означає власні контрприклади та оцінку доказів, а не повторення звіту автора.
Зберігайте команду, перевірену ревізію, результат і посилання на артефакт.
Офіційний workflow також рекомендує спостережувані перевірки та окремого verifier.
[Перевірка результатів](https://code.claude.com/docs/en/best-practices).

## Ізоляція через Git worktrees

Worktree дає окрему робочу директорію та гілку зі спільною історією Git.
Автоматичний worktree Claude за замовчуванням починається від віддаленої основної гілки.
`worktree.baseRef: "head"` обирає локальний HEAD; незакомічені зміни так не переносяться.
[Worktrees](https://code.claude.com/docs/en/worktrees).

Спочатку orchestrator створює, перевіряє та комітить новий DTO, synthetic fixtures,
OpenSpec artifacts і DAG. Перевірте clean tracked state та наявність контракту
в цьому commit. Day03 tag ще не містить цих передумов.
Для відтворюваної демонстрації оберіть саме цей checkpoint і запишіть його SHA.
Наведені команди виконуються з кореня репозиторію; назви гілок і директорій мають бути вільними.

```powershell
$checkpoint = git rev-parse HEAD
git worktree add -b codex/day04-export ../token-atlas-day04-export $checkpoint
git worktree add -b codex/day04-ui ../token-atlas-day04-ui $checkpoint
git worktree list
```

Відкривайте кожного виконавця в його worktree; саме делегування не доводить ізоляцію файлів.
У кожному checkout установіть залежності за lockfile та використовуйте окрему синтетичну БД.
Один інтегратор переглядає зміни, інтегрує коміти та запускає фінальні перевірки разом.
Worktree не усуває конфлікти контрактів, портів або зовнішніх ресурсів.
Не видаляйте робочу директорію, поки потрібні зміни не збережені та не інтегровані.

## Якщо роботу почали в Claude Code

Проєктні субагенти описуються в `.claude/agents/*.md`.
Починаючи з v2.1.198, `/agents` не відкриває старий майстер створення: редагуйте файли.
`maxTurns` обмежує кроки, `isolation: worktree` ізолює checkout виконавця.
Нижче 12 — навчальний ліміт, а не стандарт продукту.
[Субагенти Claude Code](https://code.claude.com/docs/en/subagents).

```yaml
# Приклад .claude/agents/acceptance-checker.md
---
name: acceptance-checker
description: Перевіряє change за сценаріями приймання.
tools: Read, Grep, Glob
model: inherit
maxTurns: 12
---
Зістав специфікацію, фінальний код і докази перевірок.
Шукай контрприклади, наводь файли та кроки відтворення.
Познач неперевірені твердження. Не виправляй код.
```

Поточні версії допускають вкладених субагентів; для плоскої схеми лабораторної можна задати
`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`. Наведений checker не має Agent у списку інструментів.
[Вкладене делегування](https://code.claude.com/docs/en/subagents#let-subagents-spawn-their-own-subagents).

Agent teams — окремий експериментальний режим зі спільними задачами та обміном повідомленнями.
Він вимкнений за замовчуванням; для лабораторної не потрібний.
Якщо демонструєте його додатково, врахуйте: `/resume` не відновлює in-process teammates.
[Agent teams](https://code.claude.com/docs/en/agent-teams).

## Ліміти та передача роботи

У Claude `/usage` показує використання; грошова оцінка сесії не є рахунком підписки.
`/compact` скорочує контекст, але не поновлює квоту акаунта.
Паралельні виконавці споживають додаткові ресурси: обмежуйте їх кількість і тривалість.
[Використання та витрати](https://code.claude.com/docs/en/costs).

У Claude `--max-turns` і `--max-budget-usd` працюють лише в print mode (`-p`).
Витрати субагентів входять у бюджет; зупинений через ліміт запуск не означає завершену задачу.
Значення `<CAP_USD>` нижче треба замінити власним числовим бюджетом.
[CLI reference](https://code.claude.com/docs/en/cli-reference).

```text
claude -p --max-turns 12 --max-budget-usd <CAP_USD> "Виконай обмежене доручення..."
```

Коли Claude обмежений, продовжуйте в доступній сесії Codex із тим самим репозиторієм і контрактами.
Це передача роботи; вона не скидає ліміти Claude та не гарантує доступної квоти Codex.
До переключення збережіть стислий handoff у репозиторії:

```text
Change: 06-scoped-export; checkpoint/branch/worktree: ...
Прийняті рішення та сценарії: посилання на артефакти OpenSpec.
Змінені файли, незакомічені зміни, власники незавершених задач: ...
Перевірки: команда → ревізія → фактичний результат → доказ.
Відомі дефекти та ще не виконані перевірки: ...
Наступна конкретна дія й умова зупинки: ...
```

У Codex спочатку звірте handoff із `git status`, diff і файлами, а потім продовжуйте.
Не переносьте сирі приватні логи в навчальні матеріали; використовуйте синтетичні fixtures.
Збережіть правила Token Atlas: серверна обробка, явний вибір джерел, prompts лише за явним вибором,
невідомі моделі залишаються видимими та unpriced, оцінки API не видаються за рахунки підписок.
